# 三平台 UP 主模拟器首版

## 任务定位

- 关联会话：会话-1 起的首次开发任务。
- 起始分支：`main`，空仓库，无历史提交。
- 目标：实现可直接游玩的浏览器经营游戏，在抖音、B站、小红书风格工作台中完成创作、直播、复盘和冲榜。

## 约束与决策

- 使用原生 HTML、CSS、JavaScript 模块，无运行依赖和打包步骤，便于部署与继续开发。
- 抖音使用深色侧栏与红色强调，B站使用白色侧栏与蓝色强调，小红书使用白色界面、红色强调和圆角组件。
- 账号从 1,286 位粉丝、3 条预设历史作品与 ¥3,000 资金开始；平台之间独立存档。
- 真实创作者姓名仅作为榜单挑战角色。分数和排序为模拟数据，不将虚构负面直播事件关联到真实创作者。
- 所有资金、粉丝、能量和热度变化集中在引擎，界面负责渲染及存档。

## 主要代码变更

- `creator-studio/dist/data.mjs`：平台配置、真实创作者名单、题材、热点、制作投入、直播事件与历史作品。
- `creator-studio/dist/engine.mjs`：发布、直播、日结、任务、热度排名、趋势数据和存档校验。
- `creator-studio/dist/app.js`：工作台、平台选择、作品管理、直播中心、数据分析、排行榜、灵感页和弹窗。
- `creator-studio/dist/style.css`：响应式布局、三平台主题与交互状态。
- `creator-studio/dist/assets/`：本地照片封面，不依赖外链图片。
- `creator-studio/scripts/serve.mjs`：静态预览服务器及目录访问边界。
- `creator-studio/scripts/build-standalone.mjs`：生成内嵌样式、模块与图片的单文件游戏，并检查合并后的脚本语法。
- `creator-studio/tests/engine.test.mjs`：游戏规则与连续经营回归验证。
- `AGENTS.md`、`CLAUDE.md`、`.agentdocs/index.md`、`README.md`：项目认知、运行方式和变更导航。
- `.openai/hosting.json`：站点身份及静态部署目录。

## 关键实现说明

- 视频质量影响内容基础、完播与信任；热点、平台偏好、梗和随机推荐可以让轻量作品超越高投入作品。
- 争议擦边降低口碑，有 48% 概率限流，并可能造成取关。
- 直播每次消耗 25 能量，包含 5 轮互动；关注和礼物即时入账，结束直播不重复发放。完整五轮才完成直播任务。
- 任务奖励只可领取一次，结算后重置。经营资金和累计收益分开统计。
- 日结将旧作品长尾播放与收益记入历史，恢复能量并更新热点。
- 趋势图由预设作品历史和真实游戏日结生成，末点始终对应当前账号总数；历史记录保留累计播放快照，避免历史截断导致累计趋势错误。
- 存档使用 localStorage，并在加载时校验数据。存储失败不阻塞本页游玩，会提示未保存。
- 弹窗支持 Escape、焦点限制与可见错误消息，适配小屏导航。

## 风险与限制

- 三种后台为游戏化主题还原，未接入真实平台服务。
- 创作者名单为公开姓名灵感，非实时抓取榜单；平台热度规则为游戏规则。
- 存档只在当前浏览器内，清除站点数据会丢失进度；不支持跨设备同步。
- 热点每日指游戏日轮换，非现实世界实时热搜。
